01 / THE IDEA

每一轮执行，都有小判断

Agent 工作时，需要反复决定下一步：调用什么工具、怎样处理结果、任务是否还要继续。

作者提出，把其中答案范围明确的判断交给 Jev，复杂推理和内容生成继续由主模型完成。文章给出了两个实际接入点：运行开始时选择模型，工具执行前检查风险。[1]

这里的 Harness，可以理解为让 Agent 运转起来的程序：它组织模型调用、工具执行和流程控制。Jev 的结果进入这些程序，成为下一步操作的依据。

TypeSafe 把 Jev 归为 System One 模型。它理解自然语言，输出开发者事先定义的选项、等级和概率。训练目标侧重判断与概率校准；回复用户、生成代码和解释分析过程则由生成式模型承担。[3]

原文引用厂商在分类任务上的测试，提到最高约 200 倍速度、400 倍成本优势。这些数字有特定测试条件，应用中的收益仍需实际测量。[1]

03 / MODEL ROUTING

先选好这一轮使用的模型

LangChain 的 ModelRouterMiddleware 根据最新一条用户消息，在预设模型之间选择。开发者为每个模型写明适用条件；选定后，本次运行中的模型调用沿用这个选择。[2]

一个便于理解的例子 · 补充说明“从发布记录里找出最近一个版本”可以先交给轻量模型；“分析多个服务之间的间歇性超时”可能需要更强模型。实际选择标准应参考团队自己的历史任务和评测结果。
04 / TOOL-RISK GATING

工具执行前，再检查一次

AutoModeMiddleware 用 Jev 评估工具调用的风险和授权是否充分。它只检查配置中列出的工具；判为高风险时，会返回错误消息并拦住这次调用。人工审批需要另外接入。[2]

例如，用户要求查看故障日志，Agent 却提出删除备份。我们可以把“操作是否超出请求范围”写进风险标准，让这类偏离在执行前进入检查。

注意数据边界：工具参数和对话内容可能被发送给 TypeSafe。接入前应先清理凭据和敏感数据，并确认使用要求。[2]

05 / A SMALL INTEGRATION

接入从一个分类器开始

TypeSafeClassifier 接收上下文和判断题，返回按类型分组的结果。它可以放进节点或中间件里，与现有流程组合。下面用一条紧急性判断展示接口，实际运行需要 API Key。[2]

展开 Python 示例与安装命令
TERMINAL
pip install langchain-typesafe
export TYPESAFE_API_KEY="你的密钥"
PYTHON · 仅演示调用，未实测
import os
from langchain_typesafe import Noul, TypeSafeClassifier

if not os.environ.get("TYPESAFE_API_KEY"):
    raise RuntimeError("请先设置 TYPESAFE_API_KEY")

classifier = TypeSafeClassifier(
    questions={
        "urgent": Noul(
            instructions="这条消息是否需要立即处理？"
        )
    }
)

try:
    result = classifier.invoke(
        "部分用户无法登录，已有多条反馈，请尽快排查。"
    )
    print(result.nouls["urgent"].noul)
except Exception as exc:
    raise RuntimeError("分类调用失败，请检查配置与网络") from exc

使用文中的实验性中间件，还需安装 langchain-typesafe[experimental] 以及所选生成模型的集成包。实验性接口可能变化，接入时应核对官方文档并固定依赖版本。[2]

06 / ENGINEERING NOTES

落地时，把分工写清楚补充解读

1

代码管理硬约束，模型处理语义权限、数值计算和时间比较适合由代码处理。Jev 1.13 的官方限制说明列出了精确计算、多跳判断和无关上下文等弱项，也提醒开发者测试提示注入风险。[8]

2

留下“证据不足”的出口选项里可以加入“其他”或“需要复核”。概率分散时，先补充信息或交给更完整的审查流程。问题和选项的边界写得越清楚，结果越容易解释。[4][7]

3

用自己的样本确定门槛confidence 描述的是答案概率分布的集中程度。门槛需要结合错误代价和实际表现校准。建议先旁路记录，再统计漏检、误报、延迟和总费用，决定哪些低风险环节适合自动处理。[7]

TAKEAWAY / 带走这一点

频繁、答案明确的小判断，可以单独交给 Jev。
推理与生成由主模型负责，执行边界由代码守住。

建议从一处开始：已有工单的分流，或一类工具调用的风险检查。先观察它能否减少等待和复核负担，再逐步扩大范围。
